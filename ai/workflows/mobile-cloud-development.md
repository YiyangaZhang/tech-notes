# 手机发起云端开发任务的工作流笔记

> 原稿最早可见 Git 记录：2026-10-02；原稿最近 Git 修改：2026-10-02。公开版整理：2026-11-17。以上 Git 日期用于追溯，不等同于实际首次写作日期。
> 本文为通用知识整理，历史产品能力及版本细节需结合当前文档复核。

## 1 一个重要变化：开发入口从电脑转移到云端 Agent

传统模式：

    电脑

    ↓

    IDE

    ↓

    本地 AI CLI

    ↓

    修改代码

新的模式：

    手机

    ↓

    ChatGPT

    ↓

    Codex Cloud

    ↓

    GitHub

    ↓

    代码仓库

只要项目代码通过 Git 管理，并且 Codex Cloud
可以访问仓库，就可以通过手机发起开发任务。

------------------------------------------------------------------------

## 2 是否还需要远程电脑？

在这种模式下，很多情况下：

不需要。

因为以前使用远程电脑的目的通常是：

-   让 AI 有一个运行环境；
-   让 AI 可以修改代码；
-   让 AI 可以执行测试。

而 Codex Cloud 已经提供：

-   云端开发环境；
-   项目依赖安装；
-   代码执行环境；
-   Git 集成。

因此：

    手机

    +

    Codex Cloud

    +

    GitHub

可以替代部分：

    手机

    +

    远程电脑

    +

    远程桌面

的方案。

------------------------------------------------------------------------

## 3 Git 成为核心连接层

这个模式成立的前提：

GitHub 成为唯一可信代码来源。

流程：

    Codex Cloud 修改

    ↓

    Git Commit

    ↓

    GitHub保存

    ↓

    任何设备同步

因此：

-   电脑不是开发中心；
-   手机不是开发中心；
-   GitHub 才是项目中心。

------------------------------------------------------------------------

## 4 对个人开发者的意义

未来一个个人开发项目可能变成：

    需求设计
        |
        ↓
    手机提出任务

        |
        ↓

    AI Agent 开发

        |
        ↓

    GitHub 管理版本

        |
        ↓

    人工审核架构和质量

人的主要工作从：

"写每一行代码"

转变为：

-   定义目标；
-   拆解任务；
-   审核结果；
-   控制架构方向。

------------------------------------------------------------------------

## 5 使用边界

这种模式并不意味着本地开发完全消失。

本地环境仍然适合：

-   调试真实硬件；
-   查看本地数据库；
-   处理未提交文件；
-   复杂交互调试。

更合理的方式：

    Codex Cloud

    负责：
    功能开发
    重构
    测试
    代码修改


    本地环境

    负责：
    最终验证
    调试
    发布准备

------------------------------------------------------------------------

这个发现是整个 Codex Cloud 探索过程中一个重要节点：

从"AI 辅助写代码"进一步发展为：

"通过手机管理云端 AI 软件工程流程"。
